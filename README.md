# csm — Claude Code session manager

`csm` manages the session directories of [Claude Code](https://claude.com/claude-code).
It lists them, moves them together with a repository, repairs them after
a repository was moved by hand, finds orphaned ones and removes the ones
you no longer need. Run with options, it is an ordinary command-line tool.
Run without arguments, it opens a full-screen terminal interface that works
with both the keyboard and the mouse.

Designed by Maciej Bartosiak. Generated by Claude AI.

> [!WARNING]
> **This program is experimental. Use it with caution.**
> It rewrites Claude Code's own files (`~/.claude.json` and the session
> transcripts in `~/.claude/projects`). Their format is undocumented and
> changes between Claude Code versions. Back up your data before you use it
> (see [Before the first use](#before-the-first-use)).

## Claude Code compatibility

`csm` was written for **Claude Code 2.1.x**. Its knowledge of the session format comes
from versions 2.1.310–2.1.325.

Last compatibility check: `csm` 0.2.3 is compatible with Claude Code
2.1.325.

A newer Claude Code may store its sessions differently. If you have any
doubt, ask Claude Code itself to check whether `csm` still matches the
current session format before you let `csm` change anything. For example,
run Claude Code in this repository and ask:

> Compare how csm reads and rewrites session directories, `.jsonl`
> transcripts and `.claude.json` with the format used by the Claude Code
> version installed here. Is anything different?

Use `-n` (dry run) first to see what `csm` would change.

## Why

Claude Code keeps the sessions of a project in a directory named after the
project's path. When you move or rename the repository, Claude Code no longer
finds its sessions, `--resume` shows nothing, and the old entries stay in
`.claude.json` for good. `csm` moves the repository and updates every place
that remembers its path, or repairs the sessions of a repository that has
already been moved.

## Features

- **List** session directories with their state (active, orphaned,
  unavailable, unknown), number of sessions, size and last change.
- **Show** a project's sessions: start and last change, number of messages,
  git branch, session name and the first prompt.
- **Move** a repository together with its sessions: session directories of
  the repository and its subdirectories, the `cwd` fields in the
  transcripts and the entries in `.claude.json`.
- **Repair** the sessions of a repository that was moved by hand.
- **Find orphaned** session directories, whose project is gone, and suggest
  where the project may be now.
- **Remove** session directories to a trash, **restore** them, and empty the
  trash.
- **Forget** GitHub repository paths that no longer exist
  (`githubRepoPaths` in `.claude.json`).
- **Full-screen interface** with mouse support, light and dark themes, and
  a view that is remembered between runs.
- English and Polish, chosen from `LC_ALL`, `LC_MESSAGES` or `LANG`.

Safety measures:

- Nothing changes while Claude Code is running, as Claude Code rewrites
  `.claude.json` when it quits.
- `.claude.json` is copied to `.claude.json.bak` before each change.
- Only the changed values are rewritten; everything else is copied byte for
  byte. Fields `csm` does not understand pass through unchanged.
- A file present on both sides of a merge is never overwritten; it stays in
  place and is reported.
- Removal goes to a trash that is emptied only by hand.
- Symbolic links are never followed when removing or merging.

## Requirements

- macOS or Linux.
- A C11 compiler (`clang` or `gcc`) and `make` (BSD make or GNU make).

`csm` is a single binary with no dependencies beyond the system C library.
Translations and help are built into it.

## Building and installing

```sh
make
make install                  # installs /usr/local/bin/csm
```

`PREFIX` (default `/usr/local`), `DESTDIR`, `CC` and `CFLAGS` can be set on
the command line:

```sh
make install PREFIX=$HOME/.local
make uninstall PREFIX=$HOME/.local
```

`make test` runs the unit, command-line, full-screen and integration tests.
They work only in `t/test` below the repository and never touch your own
data.

## Usage

```
csm                              full-screen interface
csm -l [-oj]                     list session directories
csm -s PATH                      details and sessions of a project
csm -m [-n] SOURCE... TARGET     move a repository with its sessions
csm -F [-n] OLD NEW              repair after a manual move
csm -r [-ny] PATH...             move session directories to the trash
csm -u [-n] [ENTRY]              list the trash or restore an entry
csm -E [-ny] [ENTRY...]          empty the trash
csm -P [-ny] [REPO...]           forget GitHub paths that are gone
csm [-l|-s|-m|-F|-r|-u|-E|-P] -h help
csm -V                           program version
```

Options:

```
-n, --dry-run   show the planned changes, change nothing
-y, --yes       remove without asking (-r, -E, -P)
-o, --orphans   only orphaned session directories
-j, --json      output for scripts (with -l)
-h, --help      help; with an action option, help for it
-V, --version   program version
```

`csm -h` shows the full help, and `csm -m -h` (or any other action) shows
the help for one action.

### Examples

List all session directories, then only the orphaned ones:

```sh
csm -l
csm -lo
```

Show the sessions of a project:

```sh
csm -s ~/src/myproject
```

Move a repository with its sessions. Look at the plan first:

```sh
csm -mn ~/src/myproject ~/work/myproject
csm -m  ~/src/myproject ~/work/myproject
```

The repository was already moved by hand. Bring its sessions along:

```sh
csm -F ~/src/myproject ~/work/myproject
```

Remove the session directories of a project you no longer need, then
restore them:

```sh
csm -r ~/src/oldproject
csm -u                        # lists the trash
csm -u 20261030T120000Z-Users-me-src-oldproject
```

### Full-screen interface

Run `csm` without arguments. The list of session directories is at the top,
the details and sessions of the chosen one below it. The keys are the same
letters as the options: `m` move, `f` repair, `r` remove, `l` list, `t` trash,
`/` filter, `,` settings, `?` help, `q` quit. Space marks directories, Enter
and Tab move to the details, `o` and `O` change the sorting. The mouse
clicks, scrolls and drags the border between the panels.

### Exit status

`0` success, `1` part of the operation failed, `2` wrong usage, `3` Claude
Code is running.

### Files

| | macOS | Linux |
|---|---|---|
| Trash and settings | `~/Library/Application Support/csm` | `$XDG_DATA_HOME/csm` (`~/.local/share/csm`) |
| Remembered view | `~/Library/Application Support/csm` | `$XDG_STATE_HOME/csm` (`~/.local/state/csm`) |

`csm` reads Claude Code's data from `$CLAUDE_CONFIG_DIR`, or from `~/.claude`
and `~/.claude.json` when the variable is not set.

## Before the first use

1. Quit every Claude Code session.
2. Back up the configuration and the sessions:
   ```sh
   cp -p ~/.claude.json ~/claude.json.backup
   cp -Rp ~/.claude/projects ~/claude-projects.backup
   ```
3. Commit and push the repository you are going to move, or copy it.
4. Run the command with `-n` first and read the plan.

To go back: move the repository to its old place, then restore both files
from the backup.
